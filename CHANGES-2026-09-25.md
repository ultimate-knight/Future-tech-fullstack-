# Fixes applied — 2026-09-25

No database schema changes in this batch — just drop these files into your
existing deployment and restart the server (`npm install` not needed either,
unless your node_modules is missing/out of date).

## Backend (Future-Tech-Backend-only/backend/src/routes/)

1. **schools.js** — School Portal's "Mark as Paid / Mark as Failed" buttons
   never appeared. Root cause: the pending-payment lookup used
   `admission.paymentId`, which is only ever set *after* a payment is
   confirmed paid — so it was always null while a payment was still pending,
   and the buttons could never show up. Now looks up the most recent
   Payment record for the admission directly.

2. **admin.js — GET /payments** — Payments tab had no way to tell which
   school a payment belonged to. Now joins each payment back to its
   admission/school and returns `schoolName`; `admin.html`'s Payments table
   has a new "School" column.

3. **payments.js — POST /create-order** — Retrying a failed/abandoned
   payment ("Try Payment Again") created a brand new Payment row every
   time, leaving duplicates behind and skipping receipt/reference numbers.
   Now reuses the existing pending/failed Payment row for the same
   admission instead of creating a new one.

4. **admin.js — DELETE /students/:id** — Deleting a student from the
   admin Students tab only removed their LMS login (Student row), not
   their underlying registration (IndividualAdmission) — so they kept
   showing up as "registered" in their school's own portal. Now also
   removes the registration, its payment record(s), and quiz history, so
   the deletion is actually final everywhere.

## Frontend (Future-Tech-Site-only/site/)

5. **student-portal.html / school-portal.html** — Clicking the header logo
   sent students/schools to the public marketing home page (losing their
   place). Now links back to their own portal.

6. **student-portal.html / school-portal.html** — If the session token is
   missing or invalid, these now redirect straight to the login page
   instead of showing an empty portal shell first.

7. **student-registration-form.html** — After creating a new account,
   clicking "Go to Login" could silently log the browser into a
   *different, older* student session left over in this tab, instead of
   prompting for the new account's credentials. Now clears any leftover
   session before navigating to the login page.

8. **level2/3/4-module1-pratical.html** — These were never wired up like
   Level 1's practical page: no working Submit button, no scoring, no
   progress saved. Rebuilt to match Level 1's pattern (same questions/
   options, now with a working Submit, scoring, and progress tracking).

9. **level2/3/4-module1-quiz.html** — Quiz results were never saved
   (Progress Tracking always showed "Not attempted yet") because these
   pages were missing the `level` / `module` / `quizId` config that tells
   the quiz engine what to save results against. Added.
